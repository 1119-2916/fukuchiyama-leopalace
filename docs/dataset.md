# データセット仕様

## 概要

- 内容: 手描きイラスト
- 枚数: 30〜50 枚
- 用途: 画像生成 AI の LoRA ファインチューニング用訓練データ

## 配置ルール

- 画像は `dataset/` 配下に置く
- キャプションは画像と同名の `.txt` ファイルにし、画像と並べる
  - 例: `001.png` ↔ `001.txt`
- ファイル名は連番など、並びが安定する命名に統一する

## キャプションの付け方

Vision LLM による一括生成を使う。手順とオプションは
[captioning.md](captioning.md) を参照。

```bash
./scripts/caption_batch.sh --dry-run                    # 対象確認
./scripts/caption_batch.sh --limit 5 --trigger-word ... # 少量で試行
./scripts/caption_batch.sh --trigger-word ...           # 本番
```

## キャプション方針（暫定）

- トリガーワードは `okakikai`（2026-11-26 決定、全モデル共通）。
  各キャプションの先頭に置く
- キャプションには「LoRA に覚えさせたい共通要素」ではなく、
  画像ごとに異なる要素（ポーズ、服装、小物、背景など）を書くのが基本
- 具体的な記述粒度・タグ形式（自然文 / Danbooru タグ等）は
  対象ベースモデルごとに異なる可能性があるため、モデル決定後に確定する

## トリガーワードとは

LoRA 学習で「覚えさせたい概念そのもの」を指すための、専用の合言葉。

- 全画像のキャプションの先頭に、同じ 1 語を必ず入れる
  （例: `fukuchiyama_style, 1girl, long hair, ...`）
- 学習が進むとモデルは「この言葉 = データセット共通の画風・概念」と
  結びつけて覚える
- 生成時にプロンプトへその言葉を入れると LoRA の効果が強く出て、
  入れなければ弱まる、という引き金（トリガー）になる
- 内容を説明する言葉（`watercolor` など既存の語）は使わない。
  既存の語だとモデルが元の意味と混同するため、実在しない造語や
  固有の綴りにするのが定石
- このプロジェクトでは `okakikai` に決定した（2026-11-26、全モデル共通）。
  既存の一般語・タグとしての用例は確認されず、実在の人物／地名／
  企業名とも衝突しない造語として採用した

## 公開範囲

- データセット画像はこの公開リポジトリで公開する（2026-11-26 決定）
- コミットした画像は Git の履歴にも残るため、後から消しても
  履歴をたどれば見える。入れる前の最終確認は行うこと
