# 画像の正規化について

データセット画像のサイズ・形式がバラバラな前提で、LoRA 学習前に
何をすべきかを調査した結果と、本リポジトリの処理方針（2026-11-26 調査）。

## 結論

**外部で強制的に正方形化したり、バケット寸法へ事前に切り抜いたりは
しない。** 外部処理は「衛生処理」だけに留め、寸法の調整
（アスペクト比バケッティング、リサイズ、切り抜き）は学習ツール側に
任せる。理由: kohya sd-scripts / AI Toolkit はどちらも読み込み時に
バケッティング＋リサイズ＋クロップを内蔵しており、外部で幾何変換を
先行すると、画像の内容を捨てる上にツールの処理と競合する。

## 一般的な方法（調査結果）

- **正方形固定ではなく「面積」基準**: バケッティングは総画素数
  （例: 1024×1024 = 約1MP）を概ね一定に保ち、元のアスペクト比に
  最も近いバケットへ割り当てる。縦横を入れ替えたバケットも用意される
- **切り抜き方式**: バケットへ resize-to-cover した上で余分をクロップ
  する（余白パディングは学習では使わない）。端に触れる線画は
  切れることがあるので、原画側に余白があることが望ましい
- **アップスケールはしない**のが原則: AI Toolkit 公式 README に
  「Images are never upscaled… You do not need to crop/resize」と明記。
  kohya は既定で `bucket_no_upscale=false`（小さい画像が拡大される）
  なので、学習設定側で `true` にすること
- **寸法の倍数制約**: 高さ・幅は VAE の縮小率（8倍）× DiT のパッチ
  （2×2）= **16 の倍数**が必須。ツールによっては 32 や 64 の
  グリッドに寄せる（kohya の `bucket_reso_steps` 既定 64）
- **形式・色・透明・向き**: PNG が無難。学習ツールは ICC を見ず
  `convert("RGB")` するため、sRGB/RGB 化は外部で済ませる方が安全。
  透明部分は素の RGB 変換では不定に潰れるため、**白背景へ合成**して
  から RGB 化する。EXIF の向きは Pillow でも明示処理しないと
  反映されず、ツール側の対応も文書化されていないため、
  **外部で焼き込むのが最も重要**な工程

## モデル別の目安

全モデル共通で VAE 8倍 × パッチ2 = ストライド16px。

| モデル | 学習面積の目安 | 根拠・備考 |
|---|---|---|
| Anima | 1024² 面積（低VRAM時は768） | 公式の学習バケット仕様は無し。AI Toolkit は32倍数にスナップ、実在の学習例では kohya steps=16 / no_upscale=true の例と steps=64 のコミュニティ例が併存 |
| MOSS-Image | 1024² 面積（1MP） | 公式 USERGUIDE: 推奨 1 / 1.5 / 2MP、範囲 0.25MP〜4MP、寸法は16の倍数必須（違反はエラー）。LoRA 向け前処理の公式文書は無し |
| Z-Image | 1024² 面積 | 公式カード: 総面積 512×512〜2048×2048、任意のアスペクト比。AI Toolkit は16倍数スナップ。LoRA 向け前処理の公式文書は無し |
| FLUX.3 Klein Base | 約1MP・元のアスペクト比 | BFL 公式の学習例: 20枚、rank 32、lr 1e-4、4000 steps。公開されたバケット刻みは無し |

## 本リポジトリの処理（scripts/normalize_images.py）

外部で行うのは次だけ:

1. EXIF 向きの焼き込み
2. sRGB 前提の RGB 化（透明は白背景へ合成してから）
3. 長辺 2048px 超の原画だけダウンサイズ（アップスケールは絶対にしない）
4. PNG で保存し、画像ごとに元サイズ・適用処理・警告を
   `normalize_manifest.json` に記録

出力先はキャプションと同型:
`dataset-normalized/<実行日時>/<モデル名>/`（再生成可能なため
gitignore 対象）。面積がモデルの下限目安（512²）を下回る画像は
警告するが、拡大はしない。

使い方:

```bash
pip install Pillow   # このスクリプトだけ Pillow が必要
./scripts/normalize_images.sh --target-model moss
```

学習用フォルダの組み立てでは、正規化済みフォルダを画像ソースに使う:

```bash
./scripts/assemble_training.sh dataset-captions/<日時>/moss \
    --images dataset-normalized/<日時>/moss
```

なお学習設定側の注意: kohya では `enable_bucket=true` かつ
`bucket_no_upscale=true` を必ず設定すること（既定のままだと小さい
画像が拡大されて学習される）。
